# Phase 5 step 5: the glibc inventory (decision 0031's check)

Date: 2026-11-04. What libports, libihash, libtrivfs, `trans/hello`, a test
client and a raw libports server reach in glibc, what of that stands on
Mach, and an estimate of `sysdeps/joist` for Phase 5.

## Method

`tools/phase5/glibc-inventory.sh WORKDIR` reproduces all of it. It runs no
downloaded program.

- **Inputs**, each checked against its SHA-256 (in the script): Debian's
  hurd-amd64 `libc0.3-dev` and `libc0.3` 2.43-7 (glibc's `libc.a`, which is
  `libcrt.a`, `libmachuser.a` and `libhurduser.a`), `hurd-dev`
  0.9.git20261028-4 (the Hurd's static libraries), `gnumach-dev`
  1.8+git20261028-1, `libgcc-15-dev` 15.3.0-5; the sources of `hurd`
  0.9.git20261028 and `glibc` 2.43 (checksums as in Debian's `.dsc`).
- **Programs:** `trans/hello.c` from the Hurd, unchanged;
  `tools/phase5/client.c` (a lookup, then `io_read`, `io_seek`, `io_stat`
  and a refused `io_write`, through glibc's Hurd layer, as Phase 5's test
  client will do); `tools/phase5/portsrv.c` (a raw libports server: a
  bucket, a class, a port and a demuxer, one thread: 0031's "narrower
  scope").
- **The links:** each compiled with clang and linked statically with
  ld.lld against the Hurd's libraries and glibc, as the Hurd links them.
  `--why-extract` records every archive member pulled in and the symbol
  that pulled it. `tools/phase5/glibc-inventory.py` maps each libc member
  to its glibc source by the sysdeps order of x86_64-gnu and classifies it.
  This is 0031's "build with `sysdeps/mach` removed and list what fails",
  from the other side: every member reached, with what of it is Mach.
- **Two stand-ins**, neither of which changes what is linked: clang's
  Linux x86-64 target with the Hurd's macros, since upstream clang lacks
  `__float128` for the Hurd target (`docs/clang-inventory.md` §3; the ELF
  objects and calling convention are the same); and an empty
  `trivfs_io_S.h` in place of MIG's server header, whose prototypes are of
  routines `hello.c` defines itself (the server code is in `libtrivfs.a`).
  Running Debian's `x86_64-gnu-migcom` was declined (a downloaded binary).

## Results

Files here: `members.csv` (every member reached: archive, glibc source,
class, the programs that reach it, the Mach-layer symbols it uses
directly), `mach-interface.csv` (each Mach-layer symbol used from outside
the layer, and by whom), `*-members.txt` (each link's members),
`nested-functions.txt`.

**Nested functions** (GCC trampolines: they need an executable stack, and
clang can't build them, 0002): 11 members reached: glibc's `fd-read`,
`fd-write`, `hurdlookup`, `hurdsig`, `init-first`, `ioctl`, `lookup-at`,
`lookup-retry`, `pt-hurd-cond-timedwait`; libports' `manage-one-thread`;
libtrivfs's `startup` (the plan's one). Each is rewritten for clang.

**A narrower scope barely narrows glibc.** The raw libports server reaches
77 of the 82 symbols: a static glibc on the Hurd brings its start-up,
signal thread, descriptor table, locks and `malloc` whatever the program
does.

**A runtime of Joist's own (0031's A)** would have to give the 91 libc
functions the Hurd libraries and these programs call directly: pthread
mutexes, condition variables, rwlocks and spin locks, `malloc` and
friends, stdio (`fprintf`, `fwrite`, `fflush`, `open_memstream`), `argp`,
`argz`, `error`, `backtrace`, `sigaction`, about 30 Hurd RPCs and helpers
(`file_name_lookup`, `getauth`, `getproc`, `io_*`, `fsys_*`), and 14 Mach
calls.

## Estimate (weeks of work, Phase 5's glibc part)

Not counted here: the MIG backend (step 6), libports (8), move-grant (9),
libtrivfs and `hello` (10), which are steps of their own either way.

| Work | Weeks |
|---|---:|
| Ports and names: slots, user references, notifications, port sets and payloads as badges, reply ports | 2 |
| `mach_msg` for the Hurd layer's direct uses, and MIG's helpers | 1.5 |
| Locks: 0014 B's address-to-notification table, requeue | 1 |
| Memory: `vm_*` over `mm` and regions, `munmap`, `mprotect`, `malloc`'s arenas in a region | 1.5 |
| Tasks and threads, and `htl` on them: creation, TLS (0010), a context each, suspend, resume, exit | 2.5 |
| Start-up: `mach_init`, `_hurd_startup`, the root as the boot filesystem | 1 |
| The rest: time, CPU count, error strings, `exc_server` refused, `sched_yield` | 0.5 |
| The build: glibc cross-built with clang for the first time (0002, condition 1), `sysdeps/joist` in its configure, the 11 nested functions, clang's `__float128` | 2.5 |
| Tests: glibc's static subset, `htl` on 1, 2 and 4 CPUs, `malloc` stress | 1 |
| **Total** | **13.5** (likely 10 to 17) |

The least certain items are the first clang cross-build of glibc and
`mach_msg`'s semantics for interruptible RPCs. **It passes 0031's 6
weeks: the owner decides** to go on, to narrow the scope, or to fall back
to a runtime of Joist's own. The data for each:

- **Go on (B):** about 13.5 weeks in Phase 5; Phase 7 starts with that done
  (0031: nothing written twice).
- **Narrow:** the libports server alone reaches 77 of the 82 symbols, so
  narrowing saves well under a week of the glibc work; it could move
  libtrivfs and `hello` (step 10) later, not glibc.
- **Fall back (A):** 91 functions of a runtime of Joist's own, perhaps 6
  to 8 weeks, all of it replaced in Phase 7 by the same glibc work as B.
